# 검토 단계 (선택 모듈)

단계 검토회의로 진행을 관리하는 프로젝트를 위한 모듈이다. `kit.py init --review-preset <이름>`으로 켠다.

- **켜면:** `docs/01_*`~`04_*`가 단계 폴더가 된다. 요구사항 추적표·TBD 관리대장은 첫 단계 폴더에 들어간다. 대시보드 개요에 '검토 단계별 산출물' 카드가 생긴다(파일명 키워드로 유무를 판정).
- **끄면:** `01_requirements`·`02_interface`·`03_design`·`04_test` 기본 폴더를 쓰고 카드를 숨긴다.

프리셋(`stages.yaml`)
| 이름 | 단계 | 쓰임 |
|---|---|---|
| `defense` | SRR → SFR → PDR → CDR | 방산·체계 개발 관행 |
| `product` | REQ → SPEC → DESIGN → RELEASE | 일반 제품. 같은 구조에 이름만 바꿨다 |

**단계 이름만 바꿔 쓰기:** 설치 후 `orchestration/kit.yaml`의 `review_stages.stages[]`에서 `code`·`name`·`folder`·`artifacts`를 고치고, 폴더를 `git mv`로 맞춘다. 대시보드는 설정만 읽으므로 코드는 고칠 필요가 없다.

**용어 충돌 주의:** 단계 약어가 요구사항 식별자 안의 기호와 같을 수 있다(예: 회의 'SFR'과 기능 요구 식별자 'SFR'). 문서에서는 회의를 "SRR 회의", "SFR 단계"처럼 쓰고, 요구사항은 항상 전체 식별자로만 쓴다.

웨이브와의 연결(예)
| 웨이브 | 산출 | 단계 반영 |
|---|---|---|
| W0 | 계약 초안, 공통 규약, 시험 인프라 | 2단계: 인터페이스 요구, 기능 분할 |
| W1~W2 | 요구사항별 구현·증적 | 3단계: 구조 설계, 프로토타입 결과, 자원·지연 예산 |
| W3 + 이후 검증 | 체계 시험, 대상 환경 성능 | 4단계: 상세 설계, 시험 절차 근거 |
