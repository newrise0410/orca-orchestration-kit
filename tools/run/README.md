# 실행 격리 모듈 (선택) — `scripts/run/`

여러 AI 세션이 같은 머신에서 동시에 빌드·시험·시뮬을 돌릴 때 서로 섞이지 않게 하고, 무거운 일은 원격 머신으로 보내는 도구다.

| 파일 | 역할 |
|---|---|
| `run.sh` | 워크트리별 격리 컨테이너 실행(로컬/원격), GPU 지정, HEAVY 슬롯 |
| `run.conf` | 프로젝트 설정(접두, 이미지, 원격 기본값, 자원 상한, 회수 폴더, 제외 패턴) |
| `cleanup_hook.sh` | `cleanup_worker.sh`가 부르는 정리 훅(컨테이너·네트워크 정지, 원본 결과 보관) |
| `metrics.sh` | 동시 실행 증설 판단용 자원 지표(로컬·원격) |
| `profiles/<이름>/` | 프로젝트 종류별 격리 변수 훅. 기본 제공: `ros2` |

## 격리 원칙
1. **세션(워크트리)마다 컨테이너 1개.** 이름은 `<접두>-<워크트리>`. 떠 있으면 재사용한다.
2. **전용 docker 네트워크.** host network 금지. 포트·멀티캐스트·탐색 트래픽이 세션끼리 섞이지 않는다. 해시로 나눈 ID만으로는 충돌하므로 네트워크 격리를 기본으로 둔다.
3. **프로젝트별 격리 변수는 프로필 훅으로.** `profile_env()`가 `ISO_ENV`에 `-e KEY=VAL`을 더한다(예: ROS 2의 `ROS_DOMAIN_ID`·`GZ_PARTITION`, 웹 앱이면 DB 이름·포트 접두).
4. **같은 컨테이너 안의 병렬 시험도 격리 단위가 필요하다.** 시험 러너 기본을 순차로 두거나 시험마다 고유 자원을 준다.
5. **빌드는 컨테이너에서 한다.** 호스트 OS와 대상 환경이 다르면 직접 설치하지 말고 대상 환경 이미지를 쓴다.

## 원격 실행
```bash
RUN_REMOTE=user@build-host RUN_CPUS=16 RUN_MEM=48g scripts/run/run.sh '<빌드·시험 명령>'
```
1. `rsync`로 워크트리를 원격 `~/<RUN_REMOTE_DIR>/<워크트리>/`에 보낸다. `RUN_EXCLUDES`는 보내지 않는다 — **배포 제한 파일 패턴을 여기에 꼭 넣는다**(예: `*.pdf`, `.orca/`, 고객 자료 폴더).
2. 원격에 같은 이름의 컨테이너를 띄우고 명령을 실행한다.
3. 끝나면 `RUN_PULL_DIRS`(증적, 원본 결과)를 로컬로 회수한다. 로컬이 더 새로우면 덮어쓰지 않는다.

전제: ssh 키 인증(BatchMode), 원격 이미지, (GPU) nvidia-container-toolkit, rsync.
로컬 머신은 워커 세션 호스트로 두고 컨테이너 작업은 원격으로 보내면, 세션 수를 늘려도 로컬이 버틴다.

## GPU 지정
`RUN_GPU=1 RUN_GPU_DEVICE=<값>` — 인덱스(`0`, `0,1`), UUID(`GPU-…`), 이름 일부(대소문자·공백·`-` 무시, 예: `3090`), `all`.
- 1~2자리 숫자만 인덱스로 본다. 모델 번호(`3090`)를 인덱스로 오해하지 않는다.
- 용도별로 나눈다(예: 렌더링 GPU와 학습 GPU). 자원·GPU·이미지는 컨테이너 생성 때만 적용된다 → 바꾸려면 `--stop` 후 다시.
- GPU를 지정해도 이미지에 GPU 프레임워크가 없으면 CPU로 돈다. 학습 이미지를 따로 두고 `RUN_IMAGE`로 고른다.

## HEAVY 슬롯
`RUN_HEAVY=1`이면 슬롯 `RUN_HEAVY_SLOTS`개(flock) 중 하나를 잡을 때까지 기다렸다 실행한다(원격은 원격 머신 기준, 로컬은 `~/.cache/kit_heavy`).
- 병목은 세션 수가 아니라 **무거운 작업의 겹침**이다(다중 인스턴스 시뮬, 학습, 대규모 시나리오). 동시성 제어 단위를 자원 슬롯으로 잡는다.
- 가벼운 단위시험·모의 시나리오는 슬롯에 넣지 않는다.

## 동시 실행 증설 절차
1. 투입할 작업이 있으면 2개씩 늘린다. 5분 동안 `scripts/run/metrics.sh`로 지표를 본다.
2. 안전선(가용 RAM, swap 증가 없음, load, GPU 메모리)과 실패 징후(OOM, 비정상 종료, 시험 타임아웃 급증, API 사용량 제한)를 확인한다.
3. 한 번이라도 넘으면 증설을 멈추고 그때 수 − 2를 **실측 한도**로 `orchestration/README.md` 5장에 적는다. 돌고 있는 워커는 죽이지 않는다.

## 정리
`orchestration/kit.yaml`의 `run.cleanup_hook: scripts/run/cleanup_hook.sh`로 두면 `cleanup_worker.sh`가 워커 정리 때 컨테이너·네트워크를 정지하고, 원본 결과(`RUN_ARCHIVE_SRC`, 기본 `.runs`)를 `~/<접두>_archive/`로 옮긴다. 보관본 삭제는 사용자 판단이다.
